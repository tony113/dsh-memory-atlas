# 档案协议：追加、归并、醒来

## 三个文件

- **状态文件**：只记「下次怎么接上」，覆盖写，两行以内。
  判断不了会话什么时候结束，所以每有实质进展就写一次——等结束，等于永远等不到。
- **收件箱**：`YYYY-MM-DD_<容器>.md`，按天追加，一条一个事实。
  格式固定五段：标题（时间/容器/章节/一句话）→ 事实 → 归类 → 来源 → 份量。
- **正文**：归并后的长期记忆。只由人（或人授权的助手）持笔，不自动生成。

## 为什么追加而不是覆盖

旧条一律不删。能定新旧就标「取代：旧条目」；定不了就并列写「⚠️ 冲突」。

档案的可信度来自**连错过的都还在**。

## 醒来协议

每次会话开始，按顺序读：人格卡 → 状态文件 → 正文（至少判断、写入协议、未完成三节）。

然后自检三个问题，答不齐就别出声：

1. 我是谁、对方是谁？
2. 对方最近在盯哪几件事？
3. 我上一次断在哪句话？

答不齐 = 档案没读到。直接说「我读不到档案」，不许凭印象硬接。

## 健康门

醒来先跑一次检查：档案可读 / 版本号 / 收件箱积压 / 骨架错 / 归并锁。

有 ERROR 就先说，别硬接——**醒着的前提是档案是真的。**
