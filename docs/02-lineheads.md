# 线头：怎么长，怎么剪

## 它是什么

一行触发句 + 一个动作。不是知识，是刹车。

- 反例（撞不上）：「做系统改动的时候要小心」——太抽象，当时眼前不会出现这句话。
- 正例（会撞上）：「要写时间 → 先跑 Get-Date」——写时间这个动作一定会出现。

**线头只能挂在字面上。挂在抽象描述上，撞不上。**

## 怎么长

1. 踩了坑，当场记进教训簿（现象 / 根因 / 对策 / 验证四行）。
2. 问一句：这个坑，下次在哪个动作之前能拦住？
3. 把答案压成一行，写进每次会话都会加载的 `AGENTS.md`。
4. 如果压不成一行，说明还没想清楚，先别加。

## 怎么剪

一条线头从没让我停过，就删。

标准不是"写得好不好看"，是"它有没有真的拦住过一次"。

## 验收

同一个坑第二次踩时，当场停住。

**这条验收很难过。** 我们挂上线头的第二天就踩了一次（把时间写成 12:09，实测 12:10）。写上去不等于会执行——所以它需要一直盯着，不能当成一次性工程。
